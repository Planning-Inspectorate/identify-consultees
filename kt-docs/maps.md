# Maps

"The map" means the interactive Defra Interactive Map. The "static map" is the server-rendered image shown without JavaScript or when the interactive map fails. The rules (static map caching, Defra gotchas, GIS styling) are in [`docs/maps.md`](../docs/maps.md); this page explains how the project maps are built.

| Mode        | How                                                                                                                                                                                                                                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Interactive | Defra bundles from `/vendor/*`, started by `public/javascripts/consultees-map.js` from the page's inline JSON config                                                                                                                                                                                                                          |
| Static      | `/consultees/:caseId/results/static-map` — the boundary page's variant is `/consultees/:caseId/boundary-map` (AVIF, WebP or PNG from `Accept`) or `.../static-map.svg`. Tiles are fetched and composited by the app, with ETags and long caching (`maps/serve-static-map.ts`, `static-map.ts`, `static-map-raster.ts`, `static-map-cache.ts`) |

The project boundary page and a report category page both use the partial `views/partials/consultee-map-region.njk`; the boundary page serves its own `/boundary-map` route, and a category page's static map is `/consultees/:caseId/results/static-map` with `category`, `exclude` and `include`.

## Building the map

The results and category pages' controllers do the same steps, with helpers from `views/consultees/run-ruleset.ts` (the boundary page is simpler: `maps/boundary-map.ts` turns each stored shapefile into a dataset, no ruleset run):

1. Loads the case boundary (`resolveCase`).
2. Runs the ruleset in the Python function (`runRulesetSafely`, through `service.rulesetRunner`). It returns every consultee it found, by a condition or within the nearby radius (20km), with its reasons.
3. Builds the **search area**, the site grown by the nearby radius, and fetches display geometry for every consultee touching it (`buildSearchAreaSafely`). Areas are drawn whole and simplified by size: the larger of 25m and 1/200th of the area's width (`DISPLAY_SIMPLIFY_WIDTH_RATIO`). A parish stays at 25m and a 3,000km² county becomes about 270m, which keeps a Norwich to Tilbury page at 1.5MB rather than 3.8MB.
4. `buildCaseMapConfig` (`maps/case-geojson.ts`) makes the config: the project, the consultees and the search area, each consultee with its category's `colour` and `fillOpacity`, so both maps colour it the same. Before that, `withAuthorityRoles` marks each identified administrative authority with its `authorityRole` (see Host and bordering authorities below), which takes its colour instead.

If step 3 fails the page still renders, and its tables list every consultee, but the map shows the site alone: a run's matches carry no geometry of their own.

## Layers

| Layer              | Shows                                                                                                                                       | Style                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| The ruleset's name | Every consultee identified, one sublayer per category with a count                                                                          | Areas filled in the category colour; point categories (hospitals, harbours, generators, nuclear sites) as dots   |
| (same dataset)     | Each category's consultees only the nearby search found, as "Category: nearby, not identified (n)"                                          | Fainter: 10% fill (3% regional), thin dashed outline; dots at 45% of the colour. Drawn under the identified ones |
| Project site       | The case boundary                                                                                                                           | Red, translucent                                                                                                 |
| Ruleset buffers    | On a category's page, the site grown by each distance the ruleset's conditions find the category within, as "Ruleset buffers (1 km, 10 km)" | A dark dashed outline, nothing filled, drawn under everything                                                    |

Regional categories (police, ambulance trusts, ICBs, counties) would hide everything else at a normal fill. A category with any area covering half or more of the search area's bounding box is filled at 6% (`REGIONAL_FILL_OPACITY`) and drawn first; local areas get 35% (`LOCAL_FILL_OPACITY`). Consultees only the nearby search found (`identified: 'false'`) get `NEARBY_REGIONAL_FILL_OPACITY` and `NEARBY_LOCAL_FILL_OPACITY` instead: they aren't in the report, but show what's around the site, out to each category's distance in [`config/nearby-consultees.yaml`](../config/nearby-consultees.yaml). They always start shown; the Layers panel can hide them.

**Category colours are interim**: a 14-colour placeholder palette (`maps/category-colours.ts`), assigned in alphabetical order per map, so a category's colour can change between projects. Consultee categories aren't in the GIS Tool Styling tables and need product and design sign-off.

**Host and bordering authorities are coloured by role**, not category, so the authorities around the one the site is in stand out from it. The rulesets workbook's Category column names each administrative row's role ("B Host Authority", "A Bordering Authority"), which `parseRulesetCsv` keeps as the condition's `authorityRole`. A match found by a host condition is a host, else one found by a bordering condition is bordering (one found both ways, where the site crosses into an area that also borders another host, is a host). Each is drawn in its role's colour from [`config/map-styles/authority-roles.yaml`](../config/map-styles/authority-roles.yaml), at its category's usual opacity, and carries `authorityRole`: the interactive map keys "Category: host (n)" and "Category: bordering (n)" as sublayers of their own, the static image draws each feature's own colour, and the report's map PDF keys "Host authority" and "Bordering authority". Nearby-only context and consultees added by hand keep their category's colour.

**The buffers are the report's.** A category's page, its static image and its report PDF draw the same ones (`views/consultees/site-buffers.ts`): each distance a buffer condition finds the category within (Ambulance trusts: 1 km and 10 km; Nearby NSIPs: `nsipRadiusKm`), grown from what the run screened - the site's outline, or its bounding box - by SQL Server and simplified for display. They're outlines of the site grown by the distance, not circles, since the conditions measure from the site's edge. A category whose conditions need an area to touch or border the site has none. One that can't be drawn is logged and left off; the rest of the map still draws.

Clicking a feature selects it and a "Selected on the map" panel shows its name, category, region and distance. The Defra map has no hover; selection goes through the interact plugin (`buildSelectableLayers`, `wireFeatureDetails`).

The category pages also carry a Measure toolbar (distance, path and polygon area). `measure-plugin.mjs` is a local plugin that draws through the vendor draw plugin's adapter rather than reimplementing vertex placement, snapping and Done/Cancel chrome; `consultees-map.js` registers `defra.drawPlugin({ snapLayers })` + `createMeasurePlugin(...)` only when the page loads the draw bundle (`vendorDrawPluginJs` in the category template), so other map hosts get no Measure button. The snap layers are the map's selectable geometry (`buildSnapLayers` reuses `buildSelectableLayers`), so the draw panel's "Snap to feature" toggle is offered in every measure session — drawing or editing. Finished shapes stay on the map: clicking one (or the panel's "Edit measurement" button) re-opens it in the draw plugin's edit session, where its vertices can be dragged, inserted or deleted and the readout re-measures on `draw:edited`; cancelling an edit restores the shape and the figure. The menu's "Clear measurements" item removes every shape a session drew (the panel's Clear button removes just the latest). Interact's feature selection is suspended while a draw or edit session runs (`draw:started`/`draw:editstart` → disable; `draw:created`/`draw:edited`/`draw:cancelled` → enable) so vertex clicks don't also pick the consultee area underneath.

`consultee-labels-plugin.mjs` names every consultee on the map so identifying one doesn't need a click: it adds a MapLibre `symbol` text layer per consultee sublayer (reusing the sublayer's filter, so a label layer covers exactly the features its sublayer draws), reading each feature's `name`. Labels appear from a configured zoom — `DEFAULT_LABEL_MIN_ZOOM` (8), tunable per map with the page config's `labelMinZoom` — and MapLibre's collision detection declutters what won't fit at wider zooms; a "Consultee names" toolbar button toggles them (on by default). The plugin attaches to the dataset's own GeoJSON source, found by scanning the style for the leaf layers rather than assuming how the datasets plugin names sources, and letter-forms come from the basemap's own font stack (`basemapTextFont` — both basemaps serve OpenFreeMap's glyphs, so the fallback is Noto Sans). A Layers-panel toggle hiding a category hides its labels too (`datasets:changed` resyncs each label layer to its sibling's visibility), and a basemap swap can't strand them — they're re-added on every `idle`. Maps without a consultee dataset (the boundary page) get neither the layers nor the button.

## The consultees table's selected row

`public/javascripts/feature-row-select-plugin.mjs` mirrors the map's selection onto the category page's consultees table, both ways: clicking a row selects its consultee on the map (`interact:selectFeature`, so the selection ring and details panel appear), and selecting a consultee feature on the map greys its row (`interact:selectionchange` → `pins-consultee-row--selected`).

A row names its feature with `data-consultee-id` on its bulk-removal checkbox — the same id the features carry as `consulteeId` (the dataset's `idProperty`, so also the `featureId` selectionchange reports). Rows without one — a consultee added by name alone has nothing on the map — can't be clicked, and selecting a feature no row names (a nearby-only consultee, the project site) just un-greys. Clicking a row's own controls stays that control's job (the checkbox marks for removal, the Remove link navigates); a second click on the selected row deselects, like the map's click-to-deselect.

Programmatic selection needs the interact plugin enabled — feature-details-plugin enables it at `map:ready`, and a row clicked earlier is replayed on `interact:active`. The emit carries the feature's `properties`/`geometry` (resolved from the `datasets` array) and the `layerId` of the sublayer whose filter matches it, so listeners see exactly what a click selection carries. `wire` no-ops when the page has no consultees table (the boundary page).

## Defra map gotchas found here

- Each dataset needs an `idProperty` (`consulteeId`, `reference` for the project, `fileKey` for the boundary page's shapefiles). MapLibre drops string feature ids, so without it nothing can be selected and the console warns about "string native IDs".
- Interact `layerId`s are MapLibre layer ids: `<dataset id>-<sublayer id>` (for example `consultee-areas-identified-0`), plus `-stroke` when a sublayer has both fill and outline.
- There's no fill-opacity option; `fillOpacity` is ignored and the fill drawn solid. Put the alpha in the colour (`translucent('#55A868', 0.05)`). The map-layers demo and component examples still draw solid fills for this reason.
- A custom `symbolSvgContent` must include `{{haloColor}}`, `{{selectedColor}}` and `{{activeColor}}`, or it isn't drawn.
- A sublayer is drawn as points only if its style sets `symbol`.
- The draw adapter needs `mapStyle.id` — it builds `user_fill<id>` style expressions and crashes on a style without one (`OPENFREEMAP_STYLE` and the OS `interactiveBasemap` both set an id for this reason).
- **One interactive map per page.** The datasets plugin's `datasetRegistry` and `layerAdapter` are module-level singletons shared by every `InteractiveMap` on the page — each map's init rebinds them to itself. With two maps, `setDatasetVisibility`/`setOpacity` read and write whichever map attached last (a Layers-menu toggle applies to the wrong map when the dataset ids match), and `datasets:changed` attaches another map's state to every panel's registry. Pages must therefore render one interactive map at a time — the boundary page is safe because it has a single map. Similarly, `im-core` memoises plugin components in a global cache keyed on component identity, capturing `pluginConfig` once — always return a fresh manifest (fresh `InitComponent`) from a plugin factory, never a shared one.

## Loading state

The Defra component has no built-in "loading map" message. `im-is-loading` only hides the `<body>` until the app mounts (anti-flicker for fullscreen behaviour); there's no spinner or `loadingText` option; and a plugin manifest can't help — a plugin's `load()` runs inside `loadApp()`, after the `im-core` and provider chunks have downloaded, so nothing registered there can cover the download phase. The `middle` slot is documented for loading screens but only exists after the React app mounts, and `createRoot()` discards anything already inside the container at that point.

`map-loading-plugin.mjs` manages the overlay outside the app instead: the container is wrapped in `.app-map-loading-wrap` and the `.app-map-loading` overlay sits beside it, so it survives the React mount and covers the whole window from script execution to tiles-idle. `consultee-map-region.njk` server-renders the same markup inside the container (hidden by a `noscript` style), which the plugin adopts — moves out of the container before `replaceChildren()`/`createRoot()` would discard it — so one seamless overlay covers first paint to first idle.

Dismissal is `map:firstidle` — the first MapLibre `idle`, once style, sources and tiles have settled (the provider emits it once, `map:ready`/`map:loaded` fire earlier on `load`) — or the `.im-c-error` watcher it shares with the static fallback, or a 60s safety timeout: the provider forwards no MapLibre `error` event, so a failed style or tile fetch would otherwise leave the overlay up forever.

It only suits `behaviour: 'inline'` — buttonFirst's collapsed launcher is inside the covered area and a fullscreen app escapes the sibling overlay (`position: fixed`). A fullscreen-capable variant would need a `middle`-slot panel (post-mount coverage only) or the component gaining a loading API upstream.

## Serving map data at scale

Embedded GeoJSON in the page config is fine at current sizes. If a map ever needs more features than a page can carry (for example every project boundary nationwide), the datasets plugin offers two paths, both with backend implications:

- `dynamicGeoJSON` — the plugin fetches GeoJSON per viewport (`bbox` via `transformRequest`). Needs a backend endpoint that clips/filters by bounding box (PostGIS `ST_Intersects` + `ST_MakeEnvelope`) and honours `maxFeatures`/simplification; auth headers are supported through `transformRequest`.
- `tiles` + `sourceLayer` — vector tiles. Either generated on demand (PostGIS `ST_AsMVT` behind an endpoint) or pre-built archives. **PMTiles and FlatGeobuf need HTTP range requests**: the server (or CDN/front door in front of it) must accept `Range` headers and return `206 Partial Content` with `Accept-Ranges: bytes`. Azure Blob Storage supports ranges natively, but an app-proxied or fronted endpoint must forward the header and stream partial responses — worth verifying early, as a broken range path fails silently into full-file downloads or missing data. The bundled MapLibre provider does not register the `pmtiles://` protocol, so that would need wiring too.

## Framing

Both maps frame the search area, or the project and matches when there isn't one. If you change `buildCaseMapConfig` or the geometry helpers, check both. **Known issue:** the static image comes out much wider than the interactive map for the same centre and zoom (Hinkley Point C's spans South Wales to the south coast). Not yet investigated.

Every input that changes the rendered static image must be part of `buildStaticMapFingerprint`'s payload, or caches serve stale images.

The static image has options only the report's map PDFs use (`StaticMapBuildOptions`): `labels` names each consultee area where a label fits (on a grid over the part of the area on the map, nearest its middle, smallest areas placed first, none overlapping), `basemap: 'greyscale'` greys and lightens the basemap - tiles or Google's image - before the overlay goes on (sharp composites after its other operations, so it's a step of its own), `bufferGeojson` draws dashed outlines, each labelled on its outline above the site, and `pixelRatio` draws the image that many times the map's size, lines and labels scaled with it. Any zoom draws, not just whole ones: the basemap's tiles come from the nearest whole zoom, on a canvas scaled to match (`basemapFrame`) - and Google's static maps, which can't, are only used for a whole zoom at one pixel ratio. The labels are SVG text, which needs a font installed (see `apps/manage/Dockerfile`).
